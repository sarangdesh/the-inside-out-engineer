A collection of bottom-up introductions, engineering deep dives, and reference material across computer science, software engineering, and related disciplines.

---

## Why this exists

There is plenty of material on using frameworks, libraries, platforms, and tools. Approachable explanations of how those systems are engineered can be harder to find. The next step often leads directly to a specification, research paper, technical reference, implementation guide, or large source tree.

The Inside-Out Engineer helps bridge that gap. It develops the foundations needed to understand a subject, follows the mechanisms that make it work, and connects those mechanisms to real implementations and engineering decisions.

For example, learning to build a React application is different from understanding how a browser parses HTML, how a JavaScript engine executes code, or how React schedules and reconciles work. Both perspectives are valuable. This collection concentrates on the layers beneath the application-facing interface and the connections between them.

## The inside-out ethos

An "inside-out" explanation begins with foundations and internal mechanisms, then works outward toward observable behaviour, practical abstractions, and engineering choices.

Abstractions are part of the subject: how they are built, what guarantees they provide, what they conceal, and where their boundaries matter. Specifications establish contracts, source code shows particular implementations, and research develops ideas and evidence. The material here provides context and a path into those primary sources while distinguishing general concepts from implementation-specific behaviour.

"Introductory" describes an accessible entry point, not a limit on depth. Prerequisite concepts are developed where they help make substantial technical material approachable without removing the complexity that matters.

## Deep dives

The Inside-Out Engineer's deep dives string together a story that starts at the bottom-most (almost) layer of the
engineering stack and builds up towards the more familiar territory. An example:

> [How Websites Work: From Browser Internals to Next.js](./content/deep-dives/how-websites-work-from-browser-internals-to-nextjs.md)
> 
> A mechanism-first reference connecting browser internals, JavaScript runtimes, module loading, build tooling, React, and the Next.js App Router.

## Scope

Subjects may include programming languages and runtimes, operating systems, networks and protocols, databases, distributed systems, browsers, artificial intelligence, system architecture, and other areas of computer science and software engineering.
